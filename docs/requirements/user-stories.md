# User Stories & Acceptance Criteria

เอกสารข้อกำหนดความต้องการระดับฟังก์ชัน (User Stories) สกัดจาก Scenarios ตามหลัก INVEST พร้อมเกณฑ์การยอมรับ (Acceptance Criteria)

---

### Story US-01: อัปโหลดเอกสารเพื่อสร้างชุด Flashcards อัตโนมัติ

As a Daniel (Lifelong Learner)  
I want to อัปโหลดไฟล์ PDF หรือบทความสรุปเนื้อหาเข้าสู่ระบบ  
So that ฉันไม่ต้องเสียเวลาพิมพ์สร้างแฟลชการ์ดเองทีละใบ

**Acceptance Criteria:**

- [ ] **AC1:** Given ผู้ใช้เลือกไฟล์ PDF ขนาดไม่เกิน 20 MB When กดปุ่มสร้างการ์ด Then ระบบต้องประมวลผลและสร้างชุดแฟลชการ์ดพร้อมคำถาม-คำตอบได้สำเร็จภายใน 5 วินาที
- [ ] **AC2:** Given ไฟล์ที่อัปโหลดไม่ใช่รูปแบบที่รองรับ (เช่น .exe หรือไฟล์เสียหาย) When ผู้ใช้อัปโหลด Then ระบบต้องแสดงข้อความแจ้งเตือน "รูปแบบไฟล์ไม่ถูกต้อง" และไม่บันทึกข้อมูล
- [ ] **AC3:** Given ไฟล์ที่อัปโหลดมีขนาดเกิน 20 MB When ผู้ใช้พยายามอัปโหลด Then ระบบต้องปฏิเสธการอัปโหลดและแจ้งเตือนขนาดไฟล์สูงสุดที่อนุญาต

**Priority:** Must  
**Estimate:** L  
**Linked Scenario:** Scenario 1, Scenario 2

### Story US-02: ตรวจสอบและแก้ไขเนื้อหา Flashcard ก่อนบันทึก

As a Daniel (Lifelong Learner)  
I want to ตรวจสอบและแก้ไขข้อความคำถาม/คำตอบที่ AI สกัดมาได้  
So that ฉันมั่นใจว่าเนื้อหาถูกต้องตรงตามความเข้าใจและบริบทที่ต้องการ

**Acceptance Criteria:**

- [ ] **AC1:** Given ระบบแสดงรายการการ์ดที่สกัดได้แบบร่าง When ผู้ใช้คลิกที่ช่องข้อความคำถามหรือคำตอบ Then ผู้ใช้สามารถพิมพ์แก้ไขข้อความได้ทันที
- [ ] **AC2:** Given ผู้ใช้แก้ไขเนื้อหาการ์ดเสร็จแล้ว When กดปุ่ม "บันทึกการเปลี่ยนแปลง" Then ระบบต้องอัปเดตข้อมูลชุดการ์ดทันที
- [ ] **AC3:** Given ผู้ใช้ต้องการลบการ์ดที่ไม่เกี่ยวข้องออก When กดไอคอนถังขยะที่การ์ดนั้น Then การ์ดใบดังกล่าวต้องถูกตัดออกจากชุดก่อนการบันทึก

**Priority:** Must  
**Estimate:** M  
**Linked Scenario:** Scenario 1

### Story US-03: การทบทวนการ์ดด้วยระบบ Spaced Repetition (SRS)

As a นิ่ง (Student)  
I want to ทำการทบทวนแฟลชการ์ดตามรอบเวลาที่ระบบคำนวณให้  
So that ฉันสามารถจดจำเนื้อหาสำคัญในระยะยาวได้อย่างมีประสิทธิภาพ

**Acceptance Criteria:**

- [ ] **AC1:** Given ผู้ใช้เปิดดูชุดการ์ด When กดปุ่ม "เริ่มทบทวน" Then ระบบต้องดึงการ์ดที่ถึงกำหนดทบทวนในวันนั้นขึ้นมาแสดงทีละใบ
- [ ] **AC2:** Given ผู้ใช้ดูเฉลยหลังการ์ด When ประเมินความยาก (ง่าย / ปานกลาง / ยาก) Then ระบบต้องคำนวณรอบวันที่จะนำการ์ดใบนี้กลับมาทบทวนใหม่ตามระดับที่เลือก
- [ ] **AC3:** Given ไม่มีการ์ดที่ถึงกำหนดทบทวนในวันนั้น When ผู้ใช้เข้าสู่หน้าทบทวน Then ระบบต้องแสดงข้อความ "ทบทวนครบสำหรับวันนี้แล้ว"

**Priority:** Must  
**Estimate:** L  
**Linked Scenario:** Scenario 3

### Story US-04: แดชบอร์ดสรุปสถิติและความก้าวหน้าในการเรียนรู้

As a นิ่ง (Student)  
I want to ดูแดชบอร์ดแสดงคะแนนความแม่นยำและจำนวนการ์ดที่จำได้  
So that ฉันสามารถประเมินได้ว่าตนเองยังอ่อนในหัวข้อใดก่อนถึงวันสอบ

**Acceptance Criteria:**

- [ ] **AC1:** Given ผู้ใช้เข้าสู่หน้าแดชบอร์ดหลัก When หน้าเว็บโหลดเสร็จ Then ระบบต้องแสดงเปอร์เซ็นต์ความแม่นยำรวม และจำนวนการ์ดที่ทบทวนสำเร็จในรอบสัปดาห์
- [ ] **AC2:** Given ผู้ใช้มีหัวข้อที่มีอัตราตอบผิดสูงกว่า 40% When ดูภาพรวม Then ระบบต้องติดแท็กไฮไลต์ว่า "หัวข้อที่ควรทบทวนซ้ำ"
- [ ] **AC3:** Given ผู้ใช้ไม่มีประวัติการทบทวนมาก่อน When เข้าดูแดชบอร์ด Then ระบบต้องแสดงกราฟสถานะว่างพร้อมข้อความแนะนำให้เริ่มทบทวนชุดแรก

**Priority:** Should  
**Estimate:** M  
**Linked Scenario:** Scenario 3

### Story US-05: โหมดจับเวลาทบทวนแบบ Micro-learning (Pomodoro Timer)

As a นิ่ง (Student)  
I want to ตั้งเวลาทบทวนแบบสั้น 10–25 นาทีพร้อมตัวนับเวลาถอยหลัง  
So that ฉันสามารถใช้ช่วงเวลาพักสั้น ๆ ทบทวนบทเรียนได้อย่างมีสมาธิ

**Acceptance Criteria:**

- [ ] **AC1:** Given ผู้ใช้อยู่ในหน้าเตรียมทบทวน When เลือกโหมด "Quick Review (10 นาที)" แล้วกดเริ่ม Then ระบบต้องแสดงตัวนับเวลาถอยหลังบนหน้าจอ
- [ ] **AC2:** Given เวลาหมดลงระหว่างทำแบบฝึกหัด When นาฬิกานับถึง 00:00 Then ระบบต้องหยุดการจับเวลาและสรุปผลจำนวนการ์ดที่ทำเสร็จในรอบนั้น
- [ ] **AC3:** Given ผู้ใช้ต้องการหยุดพักก่อนเวลา When กดปุ่ม "พักชั่วคราว" Then ตัวจับเวลาต้องหยุดนิ่งและสามารถกดต่อได้

**Priority:** Should  
**Estimate:** S  
**Linked Scenario:** Scenario 3

### Story US-06: การสลับไปกรอกข้อความโดยตรงเมื่อไฟล์เอกสารมีปัญหา (Fallback Mode)

As a Daniel (Lifelong Learner)  
I want to คัดลอกและวางข้อความโดยตรงลงในกล่องข้อความเพื่อสร้างการ์ด  
So that ฉันยังสามารถสร้างแฟลชการ์ดได้แม้ไฟล์ต้นฉบับจะมีปัญหาในการอ่าน

**Acceptance Criteria:**

- [ ] **AC1:** Given ระบบไม่สามารถสกัดข้อความจาก PDF ได้ When ผู้ใช้กดเลือกแท็บ "วางข้อความโดยตรง" Then ระบบต้องแสดงกล่องรับข้อความที่รองรับตัวอักษรได้สูงสุด 5,000 ตัว
- [ ] **AC2:** Given ผู้ใช้วางข้อความลงในกล่อง When กดปุ่ม "สร้างการ์ดจากข้อความ" Then ระบบต้องสกัดสร้าง Flashcards จากข้อความดังกล่าวได้ภายใน 3 วินาที
- [ ] **AC3:** Given กล่องข้อความว่างเปล่า When ผู้ใช้กดปุ่มสร้างการ์ด Then ระบบต้องแจ้งเตือน "กรุณากรอกข้อความก่อนดำเนินการ"

**Priority:** Could  
**Estimate:** S  
**Linked Scenario:** Scenario 2

### Story US-07: การบันทึกผลการทบทวนชั่วคราวเมื่อไม่มีสัญญาณอินเทอร์เน็ต (Offline Mode)

As a นิ่ง (Student)  
I want to สามารถเปิดทบทวนการ์ดที่มีอยู่เดิมได้ต่อเนื่องแม้สัญญาณเน็ตจะหลุด  
So that การเรียนรู้ของฉันไม่ถูกขัดจังหวะระหว่างการเดินทาง

**Acceptance Criteria:**

- [ ] **AC1:** Given การเชื่อมต่ออินเทอร์เน็ตขาดหาย When ผู้ใช้กำลังทบทวนชุดการ์ด Then แอปต้องแสดงแถบแจ้งเตือน "โหมดออฟไลน์" และอนุญาตให้ตอบการ์ดต่อไปได้
- [ ] **AC2:** Given ผู้ใช้ตอบการ์ดในโหมดออฟไลน์ When แอปบันทึกผล Then ข้อมูลต้องถูกเก็บลง Local Cache ในอุปกรณ์ของผู้ใช้
- [ ] **AC3:** Given อุปกรณ์กลับมาเชื่อมต่อเครือข่ายสำเร็จ When มีการต่อเน็ต Then ข้อมูลผลการทบทวนจาก Local Cache ต้องถูก Sync ขึ้นเซิร์ฟเวอร์หลักอัตโนมัติภายใน 10 วินาที

**Priority:** Could  
**Estimate:** L  
**Linked Scenario:** Scenario 4

### Story US-08: การจัดหมวดหมู่และติดแท็กชุด Flashcards

As a Daniel (Lifelong Learner)  
I want to กำหนดหมวดหมู่และแท็ก (Tags) ให้กับชุดการ์ด  
So that ฉันสามารถค้นหาและจัดระเบียบเนื้อหาที่มาจากหลากหลายสาขาวิชาได้อย่างเป็นระบบ

**Acceptance Criteria:**

- [ ] **AC1:** Given ผู้ใช้สร้างชุดการ์ดใหม่ When อยู่ในขั้นตอนบันทึก Then ผู้ใช้สามารถเลือกหมวดหมู่หลัก (เช่น AI, Business, CS) และพิมพ์แท็กย่อยได้
- [ ] **AC2:** Given ผู้ใช้อยู่ในหน้ารวมชุดการ์ด When พิมพ์ค้นหาด้วยชื่อแท็ก Then ระบบต้องกรองแสดงเฉพาะชุดการ์ดที่มีแท็กตรงกันทันที
- [ ] **AC3:** Given ผู้ใช้ไม่ระบุหมวดหมู่ When กดบันทึก Then ระบบต้องกำหนดค่าเริ่มต้นให้อยู่ในหมวด "ทั่วไป (General)" อัตโนมัติ

**Priority:** Should  
**Estimate:** S  
**Linked Scenario:** Scenario 1
