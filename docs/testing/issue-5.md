# Issue #5 — คลังเอกสารและโน้ต

เกณฑ์: https://github.com/Software-Engineering-Concepts-2026/se-sec2-team-07/issues/5

## พฤติกรรม

- หน้า “คลังโน้ต” มีส่วนเอกสารต้นฉบับและโน้ต พร้อมช่องค้นหาเดียวจากชื่อ ชื่อไฟล์ และข้อความ (ไม่แยกตัวพิมพ์ใหญ่เล็ก)
- เพิ่ม PDF, PPTX, TXT, MD ได้ เก็บไบต์ต้นฉบับและข้อความที่อ่านได้ใน PostgreSQL หลังตรวจไฟล์สำเร็จเท่านั้น
- เอกสารแยกตามบัญชี ผู้ใช้อื่นอ่าน ดาวน์โหลด เปลี่ยนชื่อ หรือลบไม่ได้ แม้ทราบหมายเลขเอกสาร
- เปิดอ่านข้อความในหน้าเดิม ดาวน์โหลดต้นฉบับ เปลี่ยนชื่อแสดงผล และยืนยันก่อนลบได้ ชื่อไฟล์ดาวน์โหลดคงเดิม
- การลบเอกสารไม่ลบโน้ตหรือการ์ดที่สร้างไว้ก่อนหน้า โน้ตที่เชื่อมรายวิชายังคงข้อกำหนดป้องกันการลบจาก #11
- ขีดจำกัดการอ่านไฟล์เหมือน #3: 20 MB, PDF 100 หน้า, ข้อความ 60,000 ตัวอักษร; ไม่รองรับภาพสแกน

## หลักฐานที่ใช้ตรวจ

- `tests/integration/documents.test.js`: ไบต์ดาวน์โหลดตรงต้นฉบับ, ข้อมูลยังอยู่หลังเรียกใหม่, เปลี่ยนชื่อ/ลบ, แยกเจ้าของ, บังคับเข้าสู่ระบบ, ไม่เก็บไฟล์ผิดรูปแบบ, ทำชื่อดาวน์โหลดให้ปลอดภัย
- `tests/e2e/issue5.spec.js`: เพิ่ม TXT, เปิดอ่าน, ค้นหาเนื้อหาร่วมกับโน้ต, เปลี่ยนชื่อแล้วโหลดใหม่, ดาวน์โหลด, ปฏิเสธไฟล์ไม่รองรับ, ลบเอกสารโดยโน้ตยังอยู่ บน desktop/mobile
- ตัวอ่าน PDF/PPTX ใช้ชุดทดสอบของ #3 และตรวจ regression #4 #6 #11

## ข้อจำกัดและงานที่ยังไม่ทดสอบ

- เอกสารต้นฉบับแยกตามผู้ใช้ ยังไม่มีการเชื่อมเอกสารต้นฉบับหลายรายวิชา ส่วนโน้ตยังเชื่อมได้ตาม #11
- เปิดในแอปเป็นข้อความที่อ่านได้ ไม่ใช่การแสดงรูปแบบหน้า PDF หรือสไลด์ต้นฉบับ ให้ดาวน์โหลดเพื่อดูรูปแบบเดิม
- การค้นหาโหลดข้อความทั้งหมดของผู้ใช้มาค้นหาในเบราว์เซอร์ ยังไม่ทดสอบคลังขนาดใหญ่หรือผู้ใช้จำนวนมาก และยังไม่มี pagination/โควตาพื้นที่รวม
- ไฟล์ต้นฉบับเก็บในฐานข้อมูล การสำรองข้อมูลต้องรวมตาราง documents; ยังไม่ทดสอบสำรองและกู้คืนบนระบบใช้งานจริง
- ยังไม่ทดสอบเอกสารซับซ้อนจากการเรียนจริงหรือมือถือจริง และข้อจำกัด OCR/AI/กู้ร่างใน `issue-3.md` ยังไม่ถือว่าแก้แล้ว

Migration ใหม่ `004_documents.sql` ไม่แก้ migration เดิม จุดก่อนงานนี้คือ `be44d4a` เมื่อต้องย้อนโค้ดสามารถคงตารางใหม่ไว้เพื่อรักษาไฟล์ ห้ามลบตารางเพื่อย้อนเวอร์ชันโดยไม่สำรองข้อมูล
