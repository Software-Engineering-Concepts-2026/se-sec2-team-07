# Issue #7 — สถิติและหัวข้อที่ควรทบทวน

เกณฑ์: https://github.com/Software-Engineering-Concepts-2026/se-sec2-team-07/issues/7

## พฤติกรรมที่กำหนด

- “หัวข้อ” หมายถึงชุดการ์ดต้นฉบับ ไม่แยกซ้ำตามรายวิชาที่เชื่อม
- จำนวนครั้งนับทุกผลทบทวน ส่วนจำนวนใบไม่ซ้ำนับ card_id ไม่ซ้ำ ทั้งวันนี้และสะสม
- ความแม่นยำคือจำนวนครั้งที่เลือก “จำได้/ง่าย” หารจำนวนครั้งทั้งหมด เป็นการประเมินตนเอง ไม่ใช่ระบบตรวจคำตอบถูกผิด
- สถิติรายชุดแสดงจำนวนครั้ง จำนวนการ์ดไม่ซ้ำ ความแม่นยำ จำนวน “จำไม่ได้” และ “ยาก” จากประวัติทั้งหมดของผู้ใช้
- แนะนำชุดที่มีอย่างน้อย 3 ครั้งและสัดส่วนจำได้/ง่ายต่ำกว่า 70% ก่อนปัดเศษตัวเลขแสดงผล เกณฑ์นี้เป็นกติกาผลิตภัณฑ์ ไม่ใช่ผลวินิจฉัยระดับความรู้
- เรียงชุดตามสัดส่วนความแม่นยำน้อยไปมาก ตามจำนวนครั้งมากไปน้อย และ id เพื่อให้ลำดับแน่นอน ชุดที่ไม่มีประวัติไม่ปรากฏ ส่วนชุดที่มีน้อยกว่า 3 ครั้งระบุว่าข้อมูลไม่พอ
- ปุ่มทบทวนเปิดชุดนั้นผ่านระบบเดิม คิวต้องถึงกำหนดและอยู่ในเวลารายวันของ #6 ไม่มีการเปลี่ยนกำหนดทบทวนหรือข้ามงบเวลา
- กราฟ 7 วันเดิมยังอยู่ เพิ่มตารางย้อนหลัง 30 วันรวมวันนี้ตาม UTC+7 วันไม่มีผลแสดง 0 ครั้งและความแม่นยำ “—”

## ข้อจำกัดที่ต้องติดตาม

- อ้างอิงการ์ดและชุดที่ยังอยู่ในคลัง การลบต้นฉบับลบประวัติตามโครงสร้างเดิม และชื่อหัวข้อใช้ชื่อชุดปัจจุบัน
- ยังไม่แยกสถิติตามรายวิชาหรือหัวข้อย่อยภายในชุด และยังเลือกช่วงวันย้อนหลังเองไม่ได้
- ยังไม่ได้พิสูจน์ว่าเกณฑ์ 3 ครั้ง/70% เหมาะกับผู้เรียนทุกคน คำแนะนำไม่ได้ใช้ AI
- ยังไม่ทดสอบประวัติขนาดใหญ่/ผู้ใช้จำนวนมาก สถิติอ่านประวัติทั้งหมดของบัญชีมารวมผลในเซิร์ฟเวอร์
- การทดสอบมือถือใช้ขนาดจอจำลอง ไม่ใช่อุปกรณ์จริง ข้อจำกัดในเอกสาร #3 และ #5 ยังติดตามต่อ
