# Issue #11 — ใช้เนื้อหาต้นฉบับร่วมกันหลายรายวิชา

Issue: https://github.com/Software-Engineering-Concepts-2026/se-sec2-team-07/issues/11

## พฤติกรรมและการใช้งาน

1. สร้างรายวิชาในเมนู **รายวิชา** แล้วเปิดรายวิชาเพื่อกด **เพิ่มจากคลัง**
2. เลือกการ์ดหรือโน้ตเดิมและกด **เชื่อมกับวิชานี้** ใช้ต้นฉบับเดียวกันได้หลายวิชาโดยไม่สร้างสำเนา
3. คลังโน้ตรองรับข้อความที่พิมพ์/วาง หรือสกัดจาก PDF/PPTX/TXT/Markdown ไม่เก็บไฟล์ต้นฉบับ
4. รายละเอียดการ์ดและโน้ตแสดงรายวิชาที่ใช้อยู่ การแก้ต้นฉบับเตือนชื่อวิชาที่ได้รับผลก่อนบันทึก
5. **นำออกจากวิชา** และ **ลบรายวิชา** ลบเฉพาะความเชื่อมโยง เก็บการ์ด โน้ต และประวัติทบทวนไว้
6. ป้องกันการลบโน้ต การ์ด หรือชุดต้นทางที่ยังใช้ในรายวิชา ต้องนำความเชื่อมโยงออกก่อน โดย API ตรวจซ้ำด้วย
7. ทบทวนเฉพาะรายวิชาได้ การ์ดเดียวมีประวัติและกำหนดเดียวกันทุกวิชา แผนรวมไม่เพิ่มจำนวนการ์ดซ้ำและใช้เวลารายวันร่วมกันตาม Issue #6

## สัญญา API

ทุก endpoint ต้องเข้าสู่ระบบ ตรวจเจ้าของรายวิชาและต้นฉบับ การเขียนใช้ JSON รวม DELETE ที่ส่ง `{}`

- `GET/POST /api/courses`: รายการ/สร้างรายวิชา
- `GET/PUT/DELETE /api/courses/:id`: รายละเอียด/เปลี่ยนชื่อ/ลบรายวิชา
- `GET /api/courses/library`: การ์ดและโน้ตในคลังของเจ้าของ พร้อมวิชาที่เชื่อม
- `PUT/DELETE /api/courses/:id/cards/:sourceId`: เชื่อม/นำการ์ดออก
- `PUT/DELETE /api/courses/:id/notes/:sourceId`: เชื่อม/นำโน้ตออก
- `GET/POST /api/notes`, `PUT/DELETE /api/notes/:id`: คลังโน้ตและแก้ไขต้นฉบับ
- `GET /api/review?course=:id`: คิวทบทวนรายวิชา ใช้ประวัติและยอดเวลาร่วมกับคิวรวม

เชื่อมซ้ำไม่เพิ่มข้อมูลซ้ำ การลบต้นฉบับที่ยังเชื่อมคืน 409 พร้อมชื่อวิชาในข้อความผิดพลาด การเปลี่ยนชุดที่มีการลบการ์ดเชื่อมอยู่จะ rollback ทั้งรายการ

## ฐานข้อมูลและการย้อนเวอร์ชัน

จุดก่อนงานนี้: `6075188` งานแยก commit ระบบและฐานข้อมูล หน้าจอ และการทดสอบ/เอกสาร ใช้ `git revert` ย้อนจากใหม่ไปเก่าเพื่อเก็บประวัติ การย้อนโค้ดไม่ลบตารางใหม่หรือข้อมูลรายวิชา แต่โค้ดเก่าจะไม่มีการป้องกันลบต้นฉบับที่เชื่อมอยู่ จึงควรสำรองฐานข้อมูลและหยุดแก้/ลบเนื้อหาที่เชื่อมจนกว่าจะคืนเวอร์ชันที่รองรับ
