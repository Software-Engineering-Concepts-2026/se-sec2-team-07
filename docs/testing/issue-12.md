# Issue #12 — ส่งออกผลงานการเรียนรู้

เกณฑ์: https://github.com/Software-Engineering-Concepts-2026/se-sec2-team-07/issues/12

## ขอบเขตและพฤติกรรม

เมนู **ส่งออกผลงาน** (`/#/export`) เลือกชุดแฟลชการ์ด 1–20 ชุด เลือกส่งออกเนื้อหาการ์ด สรุปการเรียนรู้ หรือทั้งสองอย่าง และดาวน์โหลด HTML หรือ JSON

- HTML เป็นไฟล์อ่านได้ด้วยเบราว์เซอร์ มีรูปแบบสำหรับพิมพ์ ไม่มี script/font/image ที่ต้องเรียกจากภายนอก
- JSON เก็บข้อความเต็มและข้อมูลสรุปแบบมีโครงสร้าง ยังไม่มีระบบ import/restore JSON
- ใช้ข้อมูลที่บันทึกแล้ว ณ เวลาส่งออก ไม่รวมร่างที่ยังไม่บันทึก ไม่แก้ข้อมูลต้นฉบับหรือตารางทบทวน
- ข้อมูลทั่วไป: ชื่อผู้เรียน วันเวลาส่งออก UTC ชื่อ/หมวด/คำอธิบายของชุดที่เลือก
- เนื้อหาการ์ด: ทุกคำถาม/คำตอบทุกใบในชุดที่เลือก รวมการ์ดที่ยังไม่ถึงกำหนดทบทวน เก็บภาษาไทย Unicode และบรรทัดใหม่
- สรุปการเรียนรู้: จำนวนการ์ดทั้งหมด จำนวนการ์ดที่เคยทบทวนไม่ซ้ำ จำนวนครั้ง เวลาเป็นวินาที การกระจาย again/hard/good/easy และความแม่นยำ (good + easy)/จำนวนครั้ง ไม่มีประวัติแสดง null/ยังไม่มีข้อมูล
- สถิติเป็นการประเมินความจำด้วยตนเองจากประวัติของการ์ดที่ยังอยู่ ไม่ใช่คะแนนสอบหรือหลักฐานรับรองความสามารถ; ระบุคำอธิบายนี้ในไฟล์ด้วย
- ไม่ส่ง email รหัสผ่าน cookie token รหัสภายในฐานข้อมูล ไฟล์ต้นฉบับ โน้ต หรือชุดที่ไม่ได้เลือก
- หากชุดที่เลือกถูกลบหรือไม่ใช่ของเจ้าของ API ตอบ 404 ทั้งรายการ ไม่ส่งออกบางส่วนเงียบ ๆ
- ขนาดสูงสุด 5 MiB ตรวจทั้งข้อความต้นฉบับและไฟล์หลังจัดรูปแบบ หากเกินแจ้ง 413 ให้ลดจำนวนชุด ไม่ตัดข้อความทิ้ง
- เมื่อ API/การสร้างไฟล์ล้มเหลวแสดงข้อผิดพลาดและเก็บตัวเลือกไว้ให้ลองใหม่ เมื่อสร้างไฟล์และส่งให้ browser ดาวน์โหลดแล้วแจ้ง “สร้างไฟล์ส่งออกแล้ว” ไม่อ้างว่าบันทึกลงดิสก์แล้ว เพราะ browser/ผู้ใช้อาจยกเลิก

## API และการจัดเก็บ

`POST /api/exports` ต้องเข้าสู่ระบบ ส่ง JSON:

```json
{"deck_ids":[1,2],"include_cards":true,"include_learning":true,"format":"html"}
```

ต้องเลือกอย่างน้อยหนึ่งประเภทข้อมูล IDs ต้องเป็นจำนวนเต็มบวกไม่ซ้ำ ผลลัพธ์ `{filename,mime_type,content}` ชื่อไฟล์ `focus-portfolio-YYYY-MM-DD.html` หรือ `.json` Frontend สร้าง Blob download จากข้อความ UTF-8

Repository อ่านภายใต้ REPEATABLE READ READ ONLY transaction และตรวจเจ้าของทุกชุดก่อนอ่านเนื้อหา การ join ประวัติกรองเจ้าของด้วย HTML escape ข้อความทุกช่อง พร้อม CSP ไม่อนุญาต script/ทรัพยากรภายนอก ไม่มี migration ใหม่สำหรับ #12

## เกณฑ์ยอมรับและหลักฐาน

| เกณฑ์ | การตรวจ |
| --- | --- |
| เลือกชุด/ข้อมูล | Browser เลือกชุด ตรวจปุ่มเมื่อไม่เลือก เลือกเนื้อหาและสรุปแยกกัน |
| สร้างไฟล์ใช้นอกแอป | Browser ดาวน์โหลด HTML/JSON จริง อ่านเนื้อหาไฟล์ และเปิด HTML เพื่อตรวจหน้า |
| ข้อมูลครบตามเลือก | Unit/API/Browser ตรวจทุกการ์ด Unicode บรรทัดใหม่ ตัวเลขสถิติ และการไม่รวมชุดที่ไม่เลือก |
| แจ้งสำเร็จ/ล้มเหลว | Browser ตรวจข้อความสำเร็จ จำลอง API 503 แล้วลองใหม่ด้วยตัวเลือกเดิม |

## ข้อจำกัดที่ต้องติดตาม

- ยังไม่ deploy, ยังไม่ทดสอบการดาวน์โหลดบนโทรศัพท์จริง/Safari/Firefox หรือ browser ที่บล็อกดาวน์โหลด ทดสอบ Chrome desktop และ mobile viewport
- ยังไม่สร้าง PDF/DOCX โดยตรง ไม่ได้ตรวจคุณภาพการพิมพ์ทุกขนาดกระดาษหรือการแบ่งหน้าจริง ผู้ใช้เปิด HTML ภายนอกแอปได้
- ไม่ใช่ระบบสำรองฐานข้อมูล และไม่มีลิงก์แชร์สาธารณะ ไม่อัปโหลดหรือส่งไฟล์ให้ผู้อื่นเอง
- สถิติไม่รวมรายการที่ลบไปแล้วตาม cascade เดิม ไม่อนุมานว่าผู้เรียนมีความสามารถผ่านเกณฑ์ใด
- ขนาดใหญ่เกิน 5 MiB ถูกปฏิเสธ ไม่มีการแบ่งไฟล์อัตโนมัติ ยังไม่ทดสอบ load/concurrent export จำนวนมาก
- ข้อจำกัด #3/#8 เกี่ยวกับ live AI และเอกสารซับซ้อน รวมถึง #9 timer และ #10 offline/deployment ยังคงอยู่
