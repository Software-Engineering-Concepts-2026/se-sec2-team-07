# Issue #4 — ตรวจและแก้ไขแฟลชการ์ดก่อนบันทึก

ขอบเขต: https://github.com/Software-Engineering-Concepts-2026/se-sec2-team-07/issues/4

## พฤติกรรม

- แสดงการ์ดที่สร้างเป็นร่างก่อนบันทึก ผู้ใช้แก้คำถามและคำตอบได้
- ลบการ์ดออกจากร่างและคืนการ์ดที่ลบล่าสุดได้หลายครั้งตามลำดับย้อนกลับ จนกว่าจะบันทึกหรือออกจากหน้า
- การลบการ์ดเดิมมีผลต่อฐานข้อมูลเมื่อกดบันทึกเท่านั้น
- แจ้งเลขการ์ดที่กรอกไม่ครบ และไม่ส่งข้อมูลที่ว่างไปบันทึก
- เมื่อบันทึกผิดพลาด ร่างยังอยู่บนหน้าและกดบันทึกใหม่ได้ ร่างยังไม่รองรับการกู้คืนหลังปิดหรือโหลดหน้าใหม่
- จำกัดชุดการ์ดไม่เกิน 500 ใบ รวมทั้งการสร้างเพิ่มและการคืนการ์ด

## หลักฐานการทดสอบ 2026-09-15

`tests/e2e/issue4.spec.js` ครอบคลุม Acceptance Criteria ทั้ง 5 ข้อ โดยจำลองผลลัพธ์ AI ที่ฝั่งเบราว์เซอร์ แต่ใช้ API และ PostgreSQL จริงสำหรับบันทึก/อ่านข้อมูล:

1. แสดงร่าง 3 ใบและตรวจว่ายังไม่มีชุดการ์ดในฐานข้อมูล
2. แก้ทั้งคำถามและคำตอบ
3. ลบการ์ดกลางชุด คืนการ์ด และตรวจว่าข้อความที่แก้ไม่หาย
4. ตรวจช่องว่าง จำลองการบันทึกล้มเหลว และลองบันทึกใหม่สำเร็จ
5. โหลดหน้าใหม่ ตรวจข้อความและจำนวนการ์ด รวมถึงลบการ์ดเดิมแล้วบันทึกซ้ำ

ผล: browser tests ทั้งชุด 4/4 ผ่าน (desktop และ mobile), unit tests 6/6 ผ่าน, production build ผ่าน

ยังไม่ได้เรียกบริการ AI จริง จึงไม่ยืนยันคุณภาพเนื้อหา คีย์ โควตา หรือการเชื่อมต่อผู้ให้บริการจากการทดสอบนี้
