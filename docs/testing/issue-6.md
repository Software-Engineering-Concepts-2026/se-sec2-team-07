# Issue #6 — ตารางทบทวนตามเวลาที่สะดวก

Issue: https://github.com/Software-Engineering-Concepts-2026/se-sec2-team-07/issues/6

## การใช้งาน

เปิดเมนู **ตารางทบทวน** ตั้งเวลาว่างต่อวัน 1–120 นาที (ค่าเริ่มต้น 10 นาที) แล้วกด **บันทึกเวลาและปรับตาราง** การตั้งค่าจะเก็บแยกตามบัญชีและใช้กับทุกชุดการ์ด

หน้าแสดงเวลาที่บันทึกไปแล้ว เวลาคงเหลือ จำนวนการ์ดที่เริ่มได้ และรายการการ์ดในแผน 7 วัน เมื่อกดเริ่ม ระบบเลือกการ์ดตามเวลาที่เหลือและตั้งตัวจับเวลาให้สอดคล้องกัน เมื่อหมดเวลาจะจบรอบโดยไม่ตอบการ์ดแทนผู้ใช้

## เกณฑ์รับงานและพฤติกรรม

| เกณฑ์ | การทำงาน |
| --- | --- |
| สร้างตารางจากข้อมูลการเรียน | ใช้กำหนดทบทวนของการ์ด ประวัติเวลาตอบ และเวลาที่ผู้ใช้ตั้ง |
| ปรับตามผลตอบ | จำไม่ได้: 10 นาที; ยาก: อย่างน้อย 1 วัน; จำได้: อย่างน้อย 2 วัน; ง่าย: อย่างน้อย 4 วัน โดยเพิ่มช่วงห่างตามประวัติเดิม |
| จัดลำดับการ์ด | กำหนดเก่าก่อน เมื่อกำหนดเท่ากันให้การ์ดที่มีประวัติทบทวนก่อน แล้วใช้ช่วงห่างและรหัสเพื่อให้ลำดับคงที่ |
| ไม่จัดเกินเวลาที่ตั้ง | จำนวนการ์ดคำนวณจากเวลาว่างหารด้วยเวลาเฉลี่ยต่อใบ ปัดลง ส่วนเกินเลื่อนไปวันถัดไป |
| ดูกำหนดครั้งถัดไป | แสดงแผน 7 วัน เปิดดูชื่อชุดและคำถามได้ พร้อมวันเวลาของการ์ดที่ยังไม่ถึงกำหนด |

เวลาเฉลี่ยใช้คำตอบล่าสุดไม่เกิน 100 ครั้งที่มีเวลามากกว่า 0 วินาที เริ่มต้น 30 วินาทีต่อใบ และจำกัดค่าประเมินไว้ที่ 15–120 วินาทีต่อใบ ตารางแสดงเฉพาะการทบทวนครั้งถัดไปของแต่ละใบ ไม่เดาผลตอบสำหรับการทบทวนซ้ำในอนาคต

## ขอบเขตการนับเวลา

- ใช้วันตาม Asia/Bangkok และรวมเวลาจากคำตอบที่บันทึกแล้วทุกชุดการ์ด ขั้นต่ำ 1 วินาทีต่อคำตอบ
- รอบใหม่ไม่รีเซ็ตเวลาที่ใช้ไปแล้ว การลบชุดการ์ดก็ไม่คืนเวลาของวัน
- การส่งคำตอบซ้ำด้วยรหัสเดิมไม่คิดเวลาซ้ำ และคำตอบพร้อมกันถูกจัดลำดับก่อนปรับยอดเวลา
- เวลาที่อ่านแต่ยังไม่บันทึกคำตอบ (รวมการจบรอบ ปิดหน้า หรือเวลาหมดกลางการ์ด) ไม่ถูกเก็บในยอดรายวัน เวลาพักไม่นับในตัวจับเวลา
- เป็นการตั้งจำนวนนาทีต่อวัน ไม่ใช่ปฏิทินนัดหมาย ไม่มีการเชื่อมปฏิทินหรือแจ้งเตือน และยังไม่มีการตั้งเวลาแตกต่างกันในแต่ละวันของสัปดาห์

## API และฐานข้อมูล

- `GET /api/review/plan`: แผนของผู้ใช้ที่เข้าสู่ระบบ
- `PUT /api/review/plan` พร้อม `{ "minutes": 10 }`: บันทึกเวลาและส่งแผนใหม่
- `GET /api/review?deck=...`: คิวการ์ดและเวลาคงเหลือ โดยตัวกรองชุดยังใช้ยอดเวลาร่วมทั้งบัญชี
- `POST /api/review`: บันทึกผลและเวลา พร้อมกำหนดถัดไป; ปฏิเสธเมื่อใช้เวลาประจำวันครบ

Migration `002_review_budget.sql` เพิ่ม `users.review_minutes` และ `review_days` พร้อมรวบรวมเวลาจากประวัติเดิม การเปิด server จะรัน migration อัตโนมัติ ไม่ต้องลบฐานข้อมูล

## การทดสอบ

- Unit: ความจุรายวัน การเลื่อนงานค้าง การไม่เลือกการ์ดอนาคตเร็วเกินไป ประมาณเวลาจากประวัติ วันที่ตามเวลาไทย
- Integration: บันทึก/ตรวจค่าตั้ง แยกเจ้าของ ใช้ยอดเดียวกันข้ามชุดและข้ามรอบ การเปลี่ยนวัน ผลตอบเปลี่ยนกำหนด คำตอบซ้ำ และคำตอบพร้อมกัน
- Browser: ตั้งเวลา 1 และ 2 นาทีแล้วจำนวนการ์ดเปลี่ยน โหลดใหม่ยังจำค่าเดิม ทบทวนแล้วดูแผนใหม่ และใช้งานครบเวลาของวัน ทั้ง desktop และ mobile
- ตรวจ regression ของ Issue #4 และขั้นตอนใช้งานเดิมร่วมด้วย
