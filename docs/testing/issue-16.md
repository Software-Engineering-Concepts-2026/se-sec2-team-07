# Issue #16 — จัดเก็บแฟลชการ์ดที่เรียนจบแล้ว

เกณฑ์ตรวจจาก https://github.com/Software-Engineering-Concepts-2026/se-sec2-team-07/issues/16 วันที่ 28 กันยายน 2026: เนื้อหา issue ระบุการจัดเก็บและนำกลับ แม้ชื่อ issue เดิมใช้คำว่าลบข้อมูล

## พฤติกรรมที่ตกลงใช้

- ผู้ใช้ทำเครื่องหมายเรียนจบเองเป็นรายใบ เมนู **จัดเก็บการ์ด** (`/#/archive`) แยก **ยังทบทวนอยู่** กับ **เรียนจบแล้ว** พร้อมค้นหาคำถาม คำตอบ และชื่อชุด ไม่ใช้ interval/คะแนนตัดสินเรียนจบอัตโนมัติ
- กด **เรียนจบแล้ว · จัดเก็บ** ต้องยืนยันก่อน มีผลกับการทบทวนทุกวิชาที่เชื่อมการ์ดเดียวกัน
- เก็บ ID เนื้อหา interval กำหนดเดิม ประวัติทบทวน และการเชื่อมรายวิชา ไม่มีการลบต้นฉบับ
- คิวรวม คิวรายชุด คิวรายวิชา แผน 7 วัน และจำนวนการ์ดถึงกำหนด ไม่รวมการ์ดที่จัดเก็บ
- การให้คะแนนจากหน้าเก่าหลังจัดเก็บถูกปฏิเสธ 409 โดยไม่หักงบรายวันหรือเพิ่มประวัติ รายการที่เคยบันทึกสำเร็จแล้ว retry ด้วย ID เดิมยังตอบสำเร็จแบบไม่เพิ่มซ้ำ
- กด **นำกลับมาทบทวน** คืนการ์ดเดิมและทำให้ถึงกำหนดทันที (due = min(due เดิม, เวลาปัจจุบัน)) โดยเก็บ interval และประวัติ จากนั้นเข้าคิวภายใต้งบรายวันเดิม ไม่รับประกันว่าการ์ดจะขึ้นเป็นใบแรก
- หน้ารายวิชาและ Editor แสดงป้ายเรียนจบ แต่ยังอ่าน/แก้เนื้อหาต้นฉบับได้ การแก้ข้อความไม่ยกเลิกสถานะจัดเก็บ
- สถิติเดิมและการส่งออก #12 ยังคงรวมการ์ดกับประวัติที่จัดเก็บ ไม่มีการนับการกดจัดเก็บเป็นผลการทบทวน
- หน้าจอดึงข้อมูลทุก 30 วินาทีเมื่อเปิดอยู่/กลับมาที่แท็บ และกดดึงล่าสุดเองได้ เมื่อบันทึกล้มเหลวรายการยังอยู่ให้ลองใหม่

## API / ฐานข้อมูล

- `GET /api/cards?archived=false` (ค่าเริ่มต้น false) หรือ `true`: `{cards:[...]}` เฉพาะเจ้าของ เรียง deck ID/card ID พร้อมชื่อชุด
- `PUT /api/cards/:id/archive` JSON `{archived:true}` หรือ `{archived:false}`: `{ok:true}` ตรวจเจ้าของและชนิด boolean อย่างเข้มงวด
- `006_card_archive.sql` เพิ่ม `cards.archived_at timestamptz` nullable; ค่า null หมายถึงยังทบทวนอยู่
- เปลี่ยนสถานะภายใต้ transaction จับ lock deck แล้ว card ให้ตรงกับการแก้/ทบทวน และเพิ่ม deck revision เมื่อสถานะเปลี่ยนเท่านั้น จึงป้องกัน Editor เวอร์ชันเก่าบันทึกทับ
- ส่งสถานะเดิมซ้ำไม่เปลี่ยน timestamp/revision/กำหนดวัน ไม่สร้างสำเนาการ์ด; archive/restore ข้ามอุปกรณ์พร้อมกันยึดคำสั่งที่ประมวลผลหลังสุด ไม่มีการรวมสถานะ

- ยังไม่ทดสอบอุปกรณ์มือถือจริง Firefox/Safari หรือปริมาณการ์ดมาก หน้าจอโหลดรายการสถานะนั้นทั้งหมด ยังไม่มี pagination หรือ bulk archive
