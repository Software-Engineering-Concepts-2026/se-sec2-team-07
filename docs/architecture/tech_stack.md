# Architectural Tech Stack & Decision Rationale

> Implementation updated 2026-09-11: the active app follows this stack. See [ADR 0002](adr/0002-implement-selected-tech-stack.md) and [Development guide](../development.md). OpenAI is the selected AI provider; no AI key is required for manual/local creation. Historical Next.js/Firebase diagrams are superseded for the active implementation.

## Tech Stack Overview (6 Layers)

| Layer                            | Choice (เทคโนโลยีที่เลือก)                   | Rationale (เหตุผลเชิง Context)                                                                                                                                                                 | Alternative (ทางเลือกอื่นที่พิจารณา)       |
| :------------------------------- | :------------------------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :----------------------------------------- |
| **1. Frontend Layer**            | React (Vite) + Plain CSS                     | • รอบ Sprint สั้น (8 สัปดาห์) ต้องการ Component-based UI ในการจัดการ State ของ Flashcard (SRS) และ Dashboard สถิติ<br>• Vite ให้เวลา Build/HMR ที่รวดเร็ว เหมาะกับนิสิตในทีม                   | Vanilla JS, Next.js, Vue.js                |
| **2. Backend / API Layer**       | Node.js + Express                            | • เหมาะสำหรับ I/O-intensive operations ในการรับ-ส่งไฟล์ PDF และการประมวลผลข้อความ<br>• เป็น JavaScript ecosystem เดียวกับ Frontend ทำให้ทีมแชร์ Data Schema และ Model interface ร่วมกันได้ง่าย | Python (FastAPI), Go, NestJS               |
| **3. Database Layer**            | PostgreSQL                                   | • รองรับ Relational Data Integrity (ACID) สำหรับข้อมูล User, Decks, Card Reviews และ SRS History<br>• มี native JSONB support สำหรับจัดเก็บ metadata ของ flashcards ที่สกัดจาก AI ได้ยืดหยุ่น  | MongoDB, MySQL, SQLite                     |
| **4. AI Integration Layer**      | Google Gemini API / OpenAI API (REST SDK)    | • ใช้สกัดสรุปเนื้อหาจากไฟล์เอกสารและสร้าง Question/Answer flashcards อัตโนมัติ (US-01)<br>• ใช้งานผ่าน HTTPS REST Calls โดยไม่ต้องบริหารจัดการโมเดลหรือ Server GPU ภายในทีม                    | Local HuggingFace Models, Anthropic Claude |
| **5. Hosting / Deployment**      | Docker + Render / Railway                    | • Containerized deployment ทำให้ environment ฝั่ง Local และ Production ตรงกัน 100%<br>• มี Free/Hobby Tier ที่เพียงพอกับ Traffic จำลองระดับวิชาเรียน (~100 daily active users)                 | AWS ECS, Vercel + Supabase                 |
| **6. Authentication & Security** | JWT (JSON Web Tokens) with HTTP-only Cookies | • Stateless Authentication ช่วยลดภาระ Session State ฝั่ง Server<br>• สามารถตรวจสอบสิทธิ์การเข้าถึงข้อมูล Dashboard และชุดการ์ดของผู้ใช้ได้อย่างรวดเร็ว                                         | Session-based (Redis), OAuth2 (Auth0)      |
