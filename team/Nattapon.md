### 2. Pragmatic Promise

ในรายวิชานี้ ผมจะให้ความสำคัญกับการเขียนโค้ดและทำงานอย่างเป็นระบบมากขึ้น โดยจะไม่ปล่อยให้ปัญหาเล็ก ๆ หรือโค้ดที่ยังไม่เรียบร้อยสะสมจนกลายเป็นปัญหาใหญ่ และจะพยายามตรวจสอบและแก้ไขสิ่งที่พบให้เร็วที่สุด

นอกจากนี้ ผมจะฝึกเขียนโค้ดให้คนอื่นสามารถอ่านและเข้าใจได้ง่าย พร้อมทั้งใช้ Git และการจัดการงานอย่างเป็นระบบมากขึ้นในการทำงานร่วมกับผู้อื่น

### 3. ทำไมอยากเรียน Software Engineering (SE)

ผมอยากเรียน Software Engineering เพราะการพัฒนาซอฟต์แวร์ไม่ได้มีแค่การเขียนโปรแกรมให้ใช้งานได้ แต่ยังต้องคำนึงถึงคุณภาพ การบำรุงรักษา และการทำงานร่วมกับผู้อื่นด้วย ผมจึงอยากเรียนรู้แนวคิดและกระบวนการที่ช่วยให้สามารถพัฒนาซอฟต์แวร์ที่มีคุณภาพและสามารถนำไปใช้งานจริงได้ในระยะยาว

### 4. Broken Window ที่เคยเจอ

**เหตุการณ์:** ในการทำงานกลุ่มที่ผ่านมา เคยมีกรณีที่สมาชิกบางคนเขียนโค้ดโดยไม่ได้จัดรูปแบบหรือกำหนดชื่อไฟล์และตัวแปรให้เป็นมาตรฐาน ทำให้ในช่วงแรกดูเหมือนเป็นปัญหาเล็ก ๆ และยังสามารถทำงานต่อได้

**ลักษณะปัญหา:** เมื่อเวลาผ่านไป สมาชิกคนอื่นเริ่มเขียนโค้ดตามรูปแบบที่ไม่เป็นระเบียบเดียวกัน ทำให้โค้ดมีรูปแบบหลากหลายและอ่านหรือแก้ไขได้ยากขึ้น

**ผลกระทบ:** เมื่อโปรเจกต์มีขนาดใหญ่ขึ้น การค้นหาจุดที่ต้องแก้ไขใช้เวลามากขึ้น และเกิดความสับสนในการทำงานร่วมกัน เพราะแต่ละคนมีรูปแบบการเขียนโค้ดที่แตกต่างกัน

**หากแก้ทันที:**
หากตั้งแต่แรกมีการกำหนดมาตรฐานการเขียนโค้ดและแก้ไขส่วนที่ไม่เป็นระเบียบตั้งแต่พบปัญหา จะช่วยป้องกันไม่ให้ปัญหาเล็ก ๆ ขยายตัวเป็นปัญหาใหญ่ ลดเวลาในการแก้ไขภายหลัง และทำให้สมาชิกทุกคนสามารถทำงานร่วมกันได้ง่ายขึ้น
